Stepper

A stepper guides users through a multi-step process by displaying all steps and indicating progress. It can be used when a task is divided into a fixed sequence of distinct steps that benefit from being shown as a whole. It is less suitable for short tasks of one or two steps, or branching processes where the next step depends on previous answers.

Accessibility Features

= Required = Recommended
  • A stepper is wrapped in a <nav> landmark with a descriptive aria-label to identify its purpose as a specific navigation region
  • aria-current="step" identifies the current step
  • Upcoming step controls are marked disabled, so screen readers and keyboard users know they cannot yet be navigated to
  • Use <button> for the controls when the stepper navigates dynamically without a page reload. Use <a> when each step has its own URL
  • When the user navigates to a new step, the keyboard focus must be moved to the beginning of the step content. If the element that receives focus is not a focusable element by default, it must have a tabindex="-1"
  • If the stepper is long, it must scale to mobile screens without overflowing. One way to achieve this is by stacking the steps vertically on smaller screens
  • An ordered list (<ol>) should be used to identify the stepper as a list of steps and to communicate the total number of steps to screen readers
  • Step state (completed, current, upcoming) is conveyed through icon, font weight and disabled state, not by colour alone
